# NextShop — интернет-магазин (портфолио-проект)

Полноценный e-commerce на **Next.js 14 (App Router) + Node.js + PostgreSQL (Prisma)**:
каталог товаров, корзина, оформление заказа, интеграция с платёжной системой
(Stripe) и CRM, SEO и оптимизация Core Web Vitals.

> Проект сделан как демонстрация подхода к архитектуре, а не как готовый
> к продакшену магазин. Платежи и CRM работают в **mock-режиме** по
> умолчанию — весь флоу (каталог → корзина → заказ → «оплата» →
> запись в CRM) полностью рабочий без единого внешнего ключа. Реальные
> Stripe/CRM ключи включаются одной переменной окружения — код к этому уже готов.

## Стек и почему так

| Слой | Технология | Причина выбора |
|---|---|---|
| Frontend/SSR | Next.js 14, App Router | Server Components для каталога (быстрый TTFB, SEO из коробки), Client Components только там, где нужна интерактивность (корзина, форма) |
| Backend | Node.js (Next.js Route Handlers) | Не выносил в отдельный сервис намеренно — для масштаба проекта отдельный backend увеличил бы сложность без пользы; API-роуты изолированы в `app/api/*` и легко выносятся в отдельный сервис при росте нагрузки |
| БД | PostgreSQL + Prisma | Реляционная модель подходит e-commerce (заказы/остатки/транзакции), Prisma даёт типобезопасность и понятные миграции |
| Платежи | Stripe (+ прослойка `lib/payment.ts`) | Провайдер-агностичная обёртка — переход на ЮKassa/CloudPayments требует правки одного файла |
| CRM | amoCRM-совместимый клиент (+ `lib/crm.ts`) | Интерфейс `CrmClient` — любая CRM (HubSpot, Bitrix24) подключается без изменения бизнес-логики заказа |
| Стили | Tailwind CSS | Скорость итерации + предсказуемый бандл без runtime CSS-in-JS |

## Структура проекта

```
app/
  page.tsx                 — каталог (Server Component, ISR 5 мин)
  products/[slug]/page.tsx — карточка товара (SSG + JSON-LD)
  cart/page.tsx             — корзина (Client Component)
  checkout/page.tsx         — форма оформления заказа
  checkout/success/page.tsx
  api/
    products/route.ts       — GET каталога с фильтрами
    cart/route.ts            — GET/POST/PATCH корзины (cookie-сессия)
    checkout/route.ts        — создание заказа + платёж + CRM (транзакция)
    webhooks/stripe/route.ts — подтверждение оплаты
  sitemap.ts / robots.ts     — генерация SEO-файлов из данных БД
lib/
  db.ts       — Prisma-клиент (singleton)
  cart.ts     — резолвинг корзины по httpOnly cookie
  payment.ts  — обёртка над Stripe с mock-режимом
  crm.ts      — CrmClient интерфейс + amoCRM/mock реализации
  types.ts    — форматирование денег, общие типы
prisma/
  schema.prisma — модель данных
  seed.ts        — демо-каталог (мебель/свет/текстиль/керамика)
components/
  Header.tsx, ProductCard.tsx, AddToCartButton.tsx, CartProvider.tsx
```

## Ключевые архитектурные решения

**Деньги в копейках (`priceCents: Int`).** Хранение денег во float —
классическая ошибка e-commerce-проектов, ведёт к рассинхрону копеек в
отчётах. Здесь суммы целочисленные, форматирование — в `lib/types.ts`.

**Гостевая корзина через httpOnly cookie**, а не localStorage — корзина
доступна на сервере (для SSR-подсчёта итога, для последующей привязки к
заказу), не теряется при смене устройства в рамках одной cookie-сессии,
и недоступна для чтения через JS (снижает риск XSS-угонов).

**Оформление заказа — атомарная транзакция** (`db.$transaction` в
`api/checkout/route.ts`): создание заказа, списание остатков и очистка
корзины происходят вместе или не происходят вовсе. Это исключает
рассинхрон «заказ создан, но остаток не списан».

**CRM-синхронизация не блокирует оформление заказа.** Если CRM недоступна,
покупатель всё равно получает подтверждение и ссылку на оплату; ошибка
логируется для ручной/фоновой досинхронизации. Синхронный вызов CRM в
чек-ауте — частая ошибка на реальных проектах, из-за которой недоступность
CRM роняет продажи.

**Подтверждение оплаты — через webhook, а не ответ API.** PaymentIntent
может подтвердиться асинхронно (3-D Secure, банковский перевод), поэтому
единственный надёжный источник истины об оплате — `api/webhooks/stripe`,
с проверкой подписи запроса.

## SEO

- `generateMetadata` на карточке товара — уникальные title/description/OG.
- JSON-LD `Product` (цена, наличие) на странице товара — почва для rich snippets.
- `app/sitemap.ts` формирует sitemap.xml из актуальных данных БД, а не статично.
- `app/robots.ts` закрывает `/checkout` и `/api/*` от индексации.
- Семантическая разметка (`h1`, `nav[aria-label]`, `alt` на изображениях).

## Core Web Vitals

- **LCP**: `generateStaticParams` пререндерит карточки товаров в билд-тайме;
  `next/image` с явными `sizes` и `priority` на первых 4 карточках каталога
  и на изображении товара.
- **CLS**: `next/font` инлайнит шрифты локально (без прыжка при подгрузке
  веб-шрифта), у изображений заданы контейнеры фиксированной пропорции
  (`aspect-[4/5]`), skeleton в `loading.tsx` вместо пустого экрана.
- **INP**: тяжёлые операции (добавление в корзину, чек-аут) обёрнуты в
  `useTransition`, чтобы не блокировать основной поток при клике.
- ISR (`revalidate = 300`) вместо полного SSR на каждый запрос — снижает
  TTFB под нагрузкой без потери актуальности каталога.

## Запуск локально

```bash
cp .env.example .env          # заполнить DATABASE_URL (остальное можно оставить пустым — включится mock-режим)
npm install
npm run db:migrate            # применить миграции
npm run db:seed               # наполнить каталог демо-товарами
npm run dev                   # http://localhost:3000
```

Для проверки реальной интеграции со Stripe: указать `STRIPE_SECRET_KEY`,
`STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET` из тестового режима Stripe
и прогнать вебхуки через `stripe listen --forward-to localhost:3000/api/webhooks/stripe`.

Для CRM: `CRM_PROVIDER=amocrm` + `CRM_API_URL`/`CRM_API_TOKEN`/`CRM_PIPELINE_ID`.
Без этих переменных используется `MockCrmClient` — сделки логируются в консоль.
